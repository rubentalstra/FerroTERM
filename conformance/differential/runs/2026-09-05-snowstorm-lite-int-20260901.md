machine over the same release archive. 23 of 26 comparisons agree. Three
diverge, and each is adjudicated below against the specification.

## How to run it again

Snowstorm Lite loads one edition from an RF2 archive you already hold. It
writes its Lucene index into the container, so no volume outlives the run:

```bash
docker run -d -p 127.0.0.1:8213:8080 --name=snowstorm-lite --memory=6g \
  snomedinternational/snowstorm-lite:latest \
  --index.path=/tmp/lucene-index/data --admin.password=<password>

curl -u admin:<password> \
  --form file=@data/snomed/SnomedCT_InternationalRF2_PRODUCTION_20260901T120000Z.zip \
  --form version-uri="http://snomed.info/sct/900000000000207008/version/20260901" \
  http://127.0.0.1:8213/fhir-admin/load-package
```

The upload returns when the import finishes, 5 minutes and 12 seconds here.
The readme mounts a named volume at `/app/lucene-index`; this run points
`--index.path` at a path the container user can already write instead, because
a named volume outlives `docker rm` and this comparison leaves nothing behind.
Remove it with `docker rm -f snowstorm-lite` and
`docker rmi snomedinternational/snowstorm-lite:latest`.

Then serve the same release from FerroTERM and replay the sample:

```bash
cargo build --release -p ferroterm-server
FERROTERM_INDEX=artifacts/int FERROTERM_LISTEN=127.0.0.1:8212 \
  target/release/ferroterm &

scripts/checks/differential.sh \
  --server http://127.0.0.1:8212/r4b \
  --snowstorm http://127.0.0.1:8213/fhir \
  --fhir r4b
```

## Divergences

### D1: the edition version URI (`$lookup`, FerroTERM is wrong)

FerroTERM answers `http://snomed.info/sct/449080006/version/20260901`.
Snowstorm Lite answers `http://snomed.info/sct/900000000000207008/version/20260901`.

The SNOMED CT URI Standard names the module identifier of the International
Edition as `900000000000207008`, in the examples of §2 SNOMED CT URI Space
(<https://docs.snomed.org/snomed-ct-specifications/snomed-ct-uri-standard/2-snomed-ct-uri-space>),
and the SNOMED CT Extension Guide repeats it in its edition URI examples
(<https://docs.snomed.org/snomed-ct-practical-guides/snomed-ct-extension-guide/4-logical-design/4.4-editions/4.4.2-edition-uri-examples>).
449080006 is the mapping module the International release ships beside the
core module. The specification decides this and it decides against FerroTERM.

Filed as #359, which names the cause in `Edition::identify`
(`crates/rf2/src/edition.rs`): the module dependency reference set of the
20260901 release makes 449080006 the only module that depends on others
without being depended on, so the root-module rule picks it.

### D2: `?fhir_vs=refset` (`$expand`, Snowstorm Lite is wrong)

FerroTERM expands the implicit value set to the 25 concepts of the edition
that are reference sets. Snowstorm Lite answers `400` with an
`OperationOutcome` whose diagnostics read
`ECL syntax error. Syntax error at line 1, character 0: mismatched input 'R'`,
so it routes the bare `refset` form into its ECL parser.

The FHIR SNOMED CT page defines the form. Its Implicit Value Sets section
lists `?fhir_vs=refset` as "all concept ids that correspond to reference sets
that are explicitly defined in the specified SNOMED CT edition", beside
`?fhir_vs`, `?fhir_vs=isa/[sctid]`, `?fhir_vs=refset/[sctid]`, and
`?fhir_vs=ecl/[ecl]` (<https://hl7.org/fhir/R4B/snomedct.html>).
`?fhir_vs=refset/900000000000497000` does answer on Snowstorm Lite, so only
the bare form is missing.

No FerroTERM issue. This is Snowstorm Lite's own gap, recorded here and
nowhere else. Its readme states the limit up front: the server supports the
SNOMED CT `isa` and `ecl` filters.

### D3: the `$translate` target system (`$translate`, FerroTERM is wrong)

Translating `22298006` through `?fhir_cm=447562003`, the ICD-10 complex map
reference set, FerroTERM returns `match.concept` as `{ "code": "I21.9" }`.
Snowstorm Lite returns `{ "system": "http://hl7.org/fhir/sid/icd-10", "code":
"I21.9" }`. Both agree on the code, and only FerroTERM leaves out the system.

R4B defines `ConceptMap.group.target` as "An absolute URI that identifies the
target system that the concepts will be mapped to" and names the only two
cases in which a map may leave it out: "This is not needed if the target value
set is specified and it contains concepts from only a single system. The group
target may also be omitted if all of the target element equivalence values are
'unmatched'." The implicit map FerroTERM serves specifies no target value set
and returns the equivalence `relatedto`, so neither case applies, and a client
receiving `I21.9` with no system cannot resolve it. FHIR itself publishes the
URI for the scheme, `http://hl7.org/fhir/sid/icd-10`
(<https://hl7.org/fhir/R4B/terminologies-systems.html>).

`translate-historical-same-as` agrees, because an association reference set
points at another SNOMED concept and the group names SNOMED on both sides.
The gap is the map reference sets, whose targets belong to another system.

Filed as #368.

## What the run does not cover

- Snowstorm Lite hosts one SNOMED CT edition at a time, so this pass is the
  International Edition only. The Netherlands edition has its own differential
  against the Nictiz Nationale Terminologieserver (#247).
- Snowstorm Lite supports a subset of ECL, so an expression outside that
  subset has no counterpart to compare against here. The evaluator is tested
  against the published ECL grammar and its example corpus instead
  (`crates/sct-ecl`).
- The comparison diffs one projection per answer: the display, the boolean,
  the outcome code, the set of expanded codes, and the set of translation
  targets. Everything else in a response is out of its reach by design.
- Snowstorm Lite serves R4. Parity for R5 and R6 shapes is not measured by
  this pass.
